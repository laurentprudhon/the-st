# MC68901 Multi-Function Peripheral

> The Motorola MC68901 (also MK68901 by Mostek, HC68901 by Hitachi) is the heart of the Atari ST's interrupt management, system timing, and serial communications.

> ### Correction — 2026-11-11 (ticket #28) — this is a *chip* page; the board's map wins
>
> Four things below are wrong for the board this project models (one 1040STE, CA4003290 —
> `design/board-inventory.md` §3.8). Corrected here and left in place; the register *offsets* in the
> table further down are right, the frame around them is not. Treat the page as `unconfirmed` otherwise.
>
> - **Package: DIP48**, not DIP64 (`U203`, `C025984`, 48-pin DIP). The pinout table below is not this
>   part. The real pins: `TAO` 13, `TBO` 14, `TCO` 15, `TDO` 16, `X1`/`X2` 17/18 (2.4576 MHz crystal
>   `Y200`), `TAI` 19, `TBI` 20, `IO0–IO7` 22–29, `TR` 30, `RR` 31, `IRQ` 32 (active low), `IEO` 33,
>   `IEI` 34, `CLK` 35 (the bus clock, `CLK4`), `D0–D7` 37–44, `IACK` 45, `DS` 47, `CS` 48.
> - **The map is `$FFFA01`–`$FFFA2F`.** `$FF8000`–`$FF83FF` is the Shifter's block. The MFP answers on
>   odd addresses, byte-wide — its register select is `A1–A5`, so `A0` is not decoded and the even
>   addresses alias. The five registers the datasheet calls 16-bit (`TADR`, `TBDR`, `TCDR`, `TDDR`, `SCR`)
>   are reached as one byte each on this machine, and every reference implements the counters as 8-bit
>   with data 0 meaning 256 (*corrected 2026-11-11, same day: this block first said the 16-bit registers
>   span two byte addresses — they do on the chip, but nothing on this board decodes the second one*). It
>   is a 6800-style peripheral reached through a `VPA`/`VMA` cycle.
> - **The "level" column invents levels.** The MFP drives exactly **one** line, `IRQ` (`U203.32`), into
>   the GSTMCU, which resolves it against VBL (4) and HBL (2) and drives `IPL0–IPL2`: **the MFP is level
>   6 for all sixteen of its sources** (`design/crossings.md` §4, `board-inventory.md` §4.3). No MFP
>   source has a 68000 level of its own, and "GPU operation done" is not a level-4 source on an ST —
>   level 4 is the vertical blank; the blitter's done line is `GPI3`, source 3.
> - **The priority ordering is right; the bit assignments are missing.** Source `n` sits in `IPRA` bit
>   `n−8` when `n ≥ 8`, else in `IPRB` bit `n`; priority descends with `n` (15 highest). So `IPRA` bit 7
>   = 15 (mono detect — the STE sound-frame line shares it), bit 0 = 8 (Timer B); `IPRB` bit 7 = 7 (FDC
>   and disk DMA share one line), bit 0 = 0 (Centronics busy). Timers A/B/C/D are sources 13/8/5/4.
> - **`IPRA`/`IPRB`/`ISRA`/`ISRB` are writable.** Writing a 0 to a bit clears it (pending, resp.
>   in-service); a 1 leaves it unchanged. Writing `IERA`/`IERB` also clears any pending bit whose enable
>   was just removed. Source of truth: vendored `hatari/src/mfp.c` (`MFP_PendingA_WriteByte`,
>   `MFP_InServiceA_WriteByte`, `MFP_EnableA_WriteByte`).
> - **The timer clock is `X1`/`X2` at 2.4576 MHz** (`Y200`), not the bus clock: `DATA × prescaler`
>   counts of that crystal, prescaler field ∈ {÷4, ÷10, ÷16, ÷50, ÷64, ÷100, ÷200}, field 0 = *stopped*,
>   `TACR = 0x08` = *event count* (`hatari/src/mfp.c`, `MFPDiv[]`, `MFP_StartTimer_AB`).
> - **`TAO`/`TBO`/`TCO`/`TDO` go nowhere on this board**: the timer outputs have no subscriber, so the
>   square-wave and one-pulse output shapes are not modelled. The `TAI`/`TBI` *inputs* are: `TBI` counts
>   `DE` (`board-inventory.md` §6.15), `TAI` the STE sound-frame line (§6.16).

### General Purpose I/O Register A ($FF8001)

| Bit | Function |
|-----|--
| 0 | GPI0 - Parallel port busy
| 1 | GPI1 - RS232 DCD
| 2 | GPI2 - RS232 CTS
| 3 | GPI3 - GPU op done
| 4 | GPI4 - Keyboard/MIDI
| 5 | GPI5 - FDC
| 6 | GPI6 - RS232 RI
| 7 | GPI7 - Monochrome detect

### Data Direction Register A ($FF8005)

Each bit determines if the corresponding GPI pin is input (1) or output (0):

| Bit | Default | Direction |
|-----|- -|-|
| 0 | 1 | Input (parallel port busy) |
| 1 | 1 | Input (RS232 DCD) |
| 2 | 1 | Input (RS232 CTS) |
| 3 | 0 | Output (GPU op done) |
| 4 | 1 | Input (keyboard/MIDI) |
| 5 | 1 | Input (FDC) |
| 6 | 1 | Input (RI) |
| 7 | 1 | Input (monochrome detect) |

### Timer A Control Register ($FF8019)

| Bit | Name | Description |
|-----|------|------|
| 0 | TAI | Timer A interrupt enable |
| 1 | TEA | Timer A enable |
| 2-3 | - | Unused |
| 4-5 | TMC | Timer A mode |
| 6-7 | TMS | Timer A source |

Mode options (TMC):
| TMC | Mode |
|-----|------|
| 0 | Free running (count) |
| 1 | Output square wave |
| 2 | Output one pulse |
| 3 | Event counter |

### Timer B Control ($FF801B)

Same structure as Timer A but used for screen graphics (hblank, sync).

### Timer C & D Control ($FF801D)

| Bits | Name | Description |
|-----|------|------|
| 0 | TACI | Timer C interrupt enable |
| 1 | TEC | Timer C enable |
| 2-3 | - | Unused |
| 4-5 | TMC | Timer C mode |
| 6-7 | TMS | Timer C source |
| 8 | TDCI | Timer D interrupt enable |
| 9 | TED | Timer D enable |
| 10-11 | - | Unused |
| 12-13 | TMC | Timer D mode |
| 14-15 | TMS | Timer D source |

Timer C = system clock (GSX, GEM timing, ~200 Hz)
Timer D = RS232 baud rate generator

### Timer D Baud Rate

Timer D generates the baud rate for the USART:

```
Baud Rate = f_clock / (16 × Timer D value)
```

Where f_clock = 8 MHz (system clock).

Standard baud rates:

| Baud | Timer D Value |
|------|------|
| 50 | 10000 |
| 300 | 166 |
| 1200 | 41 |
| 2400 | 20 |
| 4800 | 11 |
| 9600 | 5 |
| 19200 | 2 |
| 38400 | 1 |

## Timer Purposes on Atari ST

| Timer | Purpose |
|-------|---------|
| Timer A | Standalone / custom timing |
| Timer B | Screen graphics (hblank, sync) |
| Timer C | System timing (GSX, GEM, Desktop) - 200 Hz |
| Timer D | RS232 baud rate |
