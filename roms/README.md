# roms/

Data about the operating-system images the machine boots. **No Atari ROM is ever stored here** — not
an image, not a slice of one, not a container layer, not a test fixture.

| File | What it is |
|---|---|
| `emutos-1.4-manifest.json` | The 18 PAL EmuTOS 1.4 images the project ships: file name, size, SHA-256, CRC32, language. `etos256us.img` is listed under `excluded` — it is the NTSC image and the machine is PAL. |
| `emutos-1.4/etos256<lang>.sym` × 18 | One Hatari symbol file per shipped image: 1 695 symbols (`T`/`D`/`B`, absolute addresses, `0x%08x %s %s`), generated by EmuTOS's own `tools/map2sym.sh` from a rebuild **proven byte-identical** to the shipped image. GPLv2, like the ROM it describes; no ROM bytes are in it. |
| `emutos-1.4/etos256<lang>.src` × 18 | Where each `.sym` line is defined in the EmuTOS source: line N here describes line N there, as `<address> <type> <name> <file>:<line> <source text>`. `file:line` is the compiler's own line info; `~file:line` is located by source search (a.out stabs carry code line info only); `-` is a linker-provided symbol or an object-name marker. 1 412 of 1 695 lines located. GPLv2, same as the source it quotes. |
| `emutos-1.4-symbols.json` | The provenance of those symbols: per image the SHA-256 of the image, the linker map, the `.sym` and the `.src`, plus the exact toolchain, the build-date pin and the build/convert commands. |
| `emutos-1.4/etos256<lang>.img` × 18 | The 18 PAL images the machine boots, 262 144 B each, **present as of 2026-11-11** — fetched from the EmuTOS 1.4 release archive (`emutos-256k-1.4.zip`) and verified against the manifest: size, SHA-256 and CRC32 for all 18, plus size and SHA-256 for the excluded `etos256us.img` (19/19 bytes as recorded). GPLv2. |
| `emutos-1.4/emutos-src-1.4.tar.gz` | The release source the images are built from, 1 299 705 B, SHA-256 `98977ab2593d9ab81d6fcf9629f6781369912e3fe05c224a35147d5665749702` (the `SRC_SHA` pinned in the recipe). GPLv2. |
| `emutos-1.4/LICENSE.txt` | GPLv2, taken verbatim from the same source archive (`doc/license.txt`). |
| `tos-hashes.json` | The accept-list for a **user-supplied** Atari TOS 1.62 image: 13 PAL entries each with its provenance, the refused US entry, the structural pre-filter and the header country-code table. Unknown hashes are refused, never booted. |

The images are **in the tree since 2026-11-11** (the walking-skeleton ticket #10 delivered them). The
route was fetch-and-verify, not rebuild: hash equality is byte equality, so the route cannot change the
artefact, and `scripts/build-emutos-1.4.sh` remains the reproduction recipe (task #24 proved it 19/19).
**An image enters a run only if its SHA-256 equals the manifest's** — a `.sym` is valid for exactly the
image whose hash the JSON records, so an unverified file would be a different binary.

Reproducing a symbol file (or checking these): [`scripts/build-emutos-1.4.sh`](../scripts/build-emutos-1.4.sh)
downloads the pinned source and toolchain, rebuilds all 19 country images, fails loudly on any hash
mismatch, and with `--write-symbols` refreshes `emutos-1.4/*.sym` and `*.src`. The `.src` maps are
built by [`scripts/map2src.py`](../scripts/map2src.py), which joins the linker map (which object each
symbol came from), the objects' `-g` line info and the source tree.
