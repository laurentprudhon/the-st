# cpu-dissection — ticket #47's measurement

Not an emulator. One chip, one queue, one trace: the smallest world the CPU can be suspended in, so that
the cost of its continuations can be **removed** rather than reasoned about. Results:
[`tests/performance/FINDINGS.md` §15](../../tests/performance/FINDINGS.md).

The point of the tool is that variants differ in **exactly one thing** — how an await resolves — and that
nothing else can move between them:

| variant | what it is | built from |
|---|---|---|
| **A** | the CPU as it runs today, with a suspension and a `Resume` a bus cycle — **since #62 that is the folded shape** | `src/TheST.Machine/Cpu/*.cs`, linked unchanged |
| **B** | the same sources, every awaited answer already on the stack: no box, no continuation capture, no queue entry | the same files, `Engine.Mode = Inline` |
| **C** | the same instruction set with no `async` at all | generated by `gen.py` (the `await`s deleted) |
| **D** | A with the bus helpers folded into one leaf: one suspended frame a bus cycle instead of three | generated by `gen.py` — since #84 that is the sources unchanged in its own namespace, because #62 landed the fold in them |

**#62 landed D, so the A − D contrast is spent**: A and D now compile to the same code modulo comments, and
D's job is the control (`check` must still replay the trace to the same end state). The pre-#62 table
(FINDINGS §15) reproduces by checking the sources of record out of `115da43` before running `gen.py`; the
contrast that remains live is `A − B` (suspension) and `B − C` (the state machine).

The CPU is six partial files of one class since #78 split it into the die's blocks; `CpuDissection.csproj`
links `src/TheST.Machine/Cpu/*.cs` as a glob and `gen.py` transforms every one of them. A bench that links
a subset is a bench against another core — it stopped building for exactly that reason, and `#84`'s row 4
(`scripts/cpu-shape-check.sh`) is the row that catches it.

`Channel`, `Channels`, `Wires`, `Record` and `ValueLog` are the machine's own files, also linked, so the
logs answer searches exactly as the machine's do. What is *missing* is every other chip — so the numbers are
the CPU's own coroutine cost, and no subscription fire or SCU answer is in them (FINDINGS §15 says so).

## The trace

The workload is a real boot's bus cycles, captured once and replayed. `Trace.cs` reads two files:

- `cycles.bin` — 32 bytes a cycle, little-endian: `uint address | byte size | byte flags (1 = write,
  2 = cpu space) | ushort control | ushort writeData | ushort answer | ushort md | ushort pad |
  long asserted | long answerInstant`;
- `ipl.txt` — one `instant value` line per `IPL` record.

It was taken from `boot --frames 300` (Release, `29a849d`) with a **temporary** capture in `M68000.Cycle`
and `Engine.AppendRecord`, deleted before the commit — an in-engine instrument is rent (#58, FINDINGS §14).
To take it again, re-add those two lines, run

```sh
ST_DISSECT=/opt/data/cache/scratch/dissect validation-harness boot --frames 300 --out .../boot300
```

then `git checkout -- src/TheST.Machine/Cpu/M68000.cs src/TheST.Machine/Engine.cs` and delete the capture
class. Then the bench checks itself: at every cycle the replay must assert the same four lanes at the same
instant, and the pass ends when the trace does.

## Running it

```sh
python3 gen.py                       # writes Gen/Sync and Gen/Folded from the sources of record
dotnet build -c Release
dotnet bin/Release/net11.0/cpu-dissection.dll check      # the four variants must do the same work
dotnet bin/Release/net11.0/cpu-dissection.dll bench 6    # six alternating passes
dotnet bin/Release/net11.0/cpu-dissection.dll attr       # what a suspension allocates, by site and opcode
```

`ST_DISSECT_DIR` points at the capture directory (default `/opt/data/cache/scratch/dissect`).

## Three things that will fool you

- **A replay must start at cycle 0.** The state at any cycle depends on all the ones before it, so a window
  of the trace is not a shorter run: it is a different machine. Cut the workload by starting the *run* at 0
  and stopping earlier, never by skipping the head.
- **`GC.GetAllocatedBytesForCurrentThread` inside the awaiter sees only the engine's share.** The state
  machine box and the continuation `Action` are allocated *before* `UnsafeOnCompleted` is called, so the
  bracket has to begin at the previous suspension (`Engine.WaitForEither` keeps it). A per-await reading
  reports 48 B — the `Wake` alone — and that number is a lie of 500 B.
- **A `B - C` that looks too small is the finding, not a bug in the build.** The state machine costs 42.7 ns
  a bus cycle and the suspension costs 421: the `async` keyword is free until it suspends.
- **The bench builds with the machine's lowering.** `CpuDissection.csproj` carries
  `<Features>runtime-async=on</Features>` since #65 L1, because it compiles the CPU's sources itself: a row
  taken without it prices the compiler's state machines and is a different row. FINDINGS §19 has both, side
  by side, and neither is subtracted from the other.
