# Where inside an instruction the prefetch read lands — measured, then built

The frame a faulting instruction saves is `_irAddress` = **the address of the last program read − 2**, so the
only question that matters for the corpus's `MOVE` families is *how many reads the instruction got out before
the fault*. This file carries the measurement, the refused guess **and the answer that landed (`#74`)**, so the
next session neither re-derives it nor rebuilds the version that was already refused.

## The instrument

```bash
cd /opt/data/the-st && export DOTNET_ROOT=/opt/data/.dotnet PATH=/opt/data/.dotnet:$PATH \
       DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1
tools/validation-harness/bin/Debug/net11.0/validation-harness cpu-tests \
    --dir tests/680x0/full --file MOVE.w --reads /tmp/reads.tsv
```

One line per record: `name \t reference fetch addresses \t ours \t verdict` (the verdict is the *state*
comparison; the read lists are reported beside it, so compare them in python). Two things to look for:

- mismatches are almost always **exactly one read** apart, and in the direction *ours is one more* — a rule
  that removes a read in one place will have to add it in another, so a candidate rule's net count is what to
  measure, not its effect on the records you were looking at;
- the same (source EA, destination parity) key appearing in both the matching and the mismatching buckets is
the signal that the placement is per opcode.

**Then stop reading the table and read the oracle's source.** The corpus is generated by CLK, and CLK's
`Processors/68000/Implementation/68000Implementation.hpp` *is* the answer in code form:

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/TomHarte/CLK.git
cd CLK && git sparse-checkout set Processors/68000
grep -n "AbsoluteLong\|_prefetch_first" Processors/68000/Implementation/68000Implementation.hpp
```

## The answer (as built, `#74`)

A plain `MOVE`'s **absolute-long destination** has a state of its own — `BeginStateMode(MOVE_bw, AbsoluteLong)`
and `BeginStateMode(MOVE_l, AbsoluteLong)`, plus `MOVE_bw_AbsoluteLong_prefetch_first` /
`MOVE_l_AbsoluteLong_prefetch_first` — beside the generic `CalcEffectiveAddress(AbsoluteLong)` every other
instruction uses. Two halves:

1. **the pair for one read.** `Prefetch(); effective_address_[1].l = prefetch_.l;` — one read brings the low
   word in and the pair is built from the 32-bit register, so the address costs **one** read where the generic
   EA machine spends two (`Prefetch(); eff = prefetch_.l; Prefetch();`). This is why `CLR.w`/`ADD.w`/`AND.w`
   into `(xxx).l` were already green while `MOVE` was not.
2. **a prefetch-first class.** The state switches on the *source* mode: `DataRegisterDirect`,
   `AddressRegisterDirect` and `ImmediateData` jump to the `_prefetch_first` variant, which does
   `Prefetch(); Access(write); Prefetch();`; every other source does `Access(write); Prefetch(); Prefetch();`.
   So a register/immediate source has already issued the word after the address when the store faults and the
   read stays in the trace; a memory source's fault cancels it.

That is the entire difference between the proof pair — same opcode, same four words, same odd destination:

| record | reads: reference | ours before `#74` | ours after |
|---|---|---|---|
| `33ea [MOVE.w (d16,A2),(xxx).l]` — `$0D773361` (memory source) | 2 (`$C04`, `$C06`) | 3 | 2 ✓ |
| `33fc [MOVE.w #,(xxx).l]` — `$2C17D739` (immediate source) | 3 (`$C04`, `$C06`, `$C08`) | 3 ✓ | 3 ✓ |

In the core (`src/TheST.Machine/Cpu`): `FetchMoveAbsoluteLongAsync` (one pop, then `_pc += 2` and
`_queueShort` because the low word is taken out of the queue, not popped),
`CloseAfterLongDestinationAsync` (the two words the reference's two closing prefetches read),
`MoveSourceNeedsNoBusCycle` (the class, read off `_opcode`'s own source field — mode 0, mode 1, or mode 7/reg 4),
and the `_queueShort` reset at both instruction boundaries (`Run` and `SingleStep.Load`).

## How to prove a placement change

- `--reads` over `MOVE.w` **and** `MOVE.l`: **0** mismatched records, and the read lists of every *other*
  record in those files **unchanged** (`#74`: 49 of 16 130 changed). That is the signature that separates a
  placement from a blanket rule — the refused clause moved hundreds of records to fix 23.
- `--trace N` on the proof pair (0-based index: `--trace 17` is `33ea`): the reference's `r fc6` address list
  must match ours **in order, with the same function codes**. The residual `≠` rows are the model's internal
  `n` against this core's frame writes and the 24-bit wire truncating a data address's upper byte — both
  pre-existing and state-matching.
- then the whole set (1 000 057 / 1 000 060), the sample (2 976), the gate, and the 300-frame records.

## The refused rule, with its numbers (do not rebuild)

"A long destination address defers its last word's refill until the address is validated" — built, measured,
reverted: **999 753 / 1 000 060** (fixes 23 records, breaks 278). The reason is the `prefetch_first` class: the
reference *does* read past the address for a register/immediate source, so a clause that always defers is wrong
in exactly the cases where the reference is right today.

## The halves that ARE settled, and must not be disturbed

- one read per consumed word, so a completed instruction fetches its own word count at `pc + 4`, `pc + 6`, …;
- the trailing read is cancelled by a fault that comes first, *except* for a plain `MOVE` into `-(An)`, which
  issues it before its write and therefore keeps it in the trace;
- a destination address built from the instruction stream (`(d16,An)`, `(d8,An,Xn)`, absolute) is validated
  where it is built, i.e. before the trailing read; a `-(An)` one is validated at the bus cycle, after it;
- `MOVEM.l` into an odd `-(An)` faults on the low word at `A − 2`, the same word-at-a-time rule as `MOVE`;
- **a plain `MOVE` into `(xxx).l` is its own class** (the two halves above) — the generic EA machine is what
  every *other* instruction into the same destination uses, so do not "unify" them.
